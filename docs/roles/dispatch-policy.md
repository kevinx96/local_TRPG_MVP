# 任务分派规则（跨项目通用）

> 2026-10-20 起生效。适用于：主对话（Claude）担任决策与审查，执行工作全部交给 Codex、Antigravity 或 Claude 子代理。可以直接复制到其他项目使用。

## 1. 两条总原则

1. **主对话只做三件事：决策、分析、审查。** 读大量文件、看大批截图、写代码、写长文档、跑测试、做调研，都交出去，包括“我自己来做更快”的工作——这类工作也用子代理做。目的是让主对话的上下文只装结论，减少上下文压缩的次数。
2. **派任务之前先评估难度，再选执行方和档位。** 不用默认值一把梭：简单的给便宜的，难的才给贵的；每次派发都写下“为什么选它”。

## 2. 难度分级

| 级别 | 判断标准（满足任一即可归入） | 例子 |
|---|---|---|
| **D1 机械** | 规则明确、几乎不用判断；改动集中在少数文件；有现成脚本照做 | 改路径、补 `.uid`、批量重命名、照清单移动文件、重跑截图、整理表格、统计数字 |
| **D2 常规** | 有明确的任务说明和验收标准；改动在一个模块内；出错容易发现 | 按问题单修几处模型 / 界面、加一个检查脚本、写某个功能的说明文档、单张地图的截图审阅 |
| **D3 复杂** | 跨多个模块或系统；需要先查原因再动手；有并发、异步、时序等隐患；验收要跑大量回归 | 流程状态机、剧情演出指令系统、打包与发行检查、定位偶发失败、跨地图的共用美术库 |
| **D4 关键 / 高风险** | 改错代价大（存档格式、发行包、玩家数据）；需要大量审美或设计判断；之前已经失败过一次 | 存档迁移、全局风格方案、返工任务、第二次修同一个问题、需要读懂大量历史代码再做架构调整 |

拿不准就往上取一级；**返工任务一律至少比原任务高一级**。

## 3. 执行方与档位

### 3.1 可用的执行方（能力对标由用户 2026-10-20 提供）

| 执行方 | 档位 | 能力 / 用量 | 对标 Claude | 适合 |
|---|---|---|---|---|
| Codex · **astra 6** | low – max | Codex 里最快、最强 | Fable 5.1 | D3 / D4 工程：跨系统改动、难排查的问题、返工、审美要求高的美术实现 |
| Codex · **Sol 6.1** | low – max | 用量明显更省；max 约等于 astra high 的 70%，但耗时更长 | Opus 5.5 | D2 / D3 工程主力：有清晰说明、不赶时间的任务 |
| Codex · **Luna 6** | 只用 max | 最便宜：一直用 max，用量也不到一次 Sol 6.1 low | Haiku 5.5 | D1 机械工程：改路径、补文件、批量重命名、照清单执行、重跑截图 / 检查 |
| Antigravity · **argon** | low – high | 偏科：写作和文案公认很强，部分测试优于 Opus 和 astra；但写代码会出很蠢的基础错误，Antigravity 本身工具也差 | — | 文案、说明文档、对话台词草稿、调研总结；代码任务只在实测证明可靠后再派，派了必须由 Codex 或 Claude 复查 |
| Claude 子代理 · **Haiku 5.5** | — | 最便宜 | — | 机械的读取、检索、统计、格式整理 |
| Claude 子代理 · **Sonnet 5.5** | — | 中等 | — | 常规阅读理解、写任务说明草稿、截图初审 |
| Claude 子代理 · **Opus 5.5** | — | 强 | — | 复杂分析、审美判断、跨文件审查、问题单定级 |
| Claude 子代理 · **Fable 5.1** | — | 最强、最贵 | — | 最关键的设计判断和疑难问题；少用 |

派发参数（本机 Codex 模型 ID，2026-10-20 查 `~/.codex/models_cache.json`）：`--model gpt-6-astra`、`--model gpt-6.1-sol`、`--model gpt-6-luna`，配 `--effort low|medium|high|xhigh|max`。Antigravity 用 `--model gemini-4-argon-low|medium|high`（以 `agy models` 实际列出为准）。Claude 子代理用 Agent 工具的 `model: haiku|sonnet|opus|fable`。换到其他机器时先核对模型 ID。

### 3.2 按难度选

| 难度 | 工程实现（写代码、改资源、跑测试） | 阅读 / 分析 / 审阅 | 写作 / 文案 |
|---|---|---|---|
| D1 | **Codex Luna 6 max** | Claude Haiku | argon low |
| D2 | **Codex Sol 6.1 medium–high** | Claude Sonnet | argon medium |
| D3 | Codex Sol 6.1 max（不赶时间）或 **astra 6 high**（赶时间 / 跨系统） | Claude Opus | argon high，Claude Opus 复核 |
| D4 | **Codex astra 6 high–max** | Claude Opus；最关键的拍板用 Fable | Claude Opus 定稿 |

### 3.3 取舍规则

- **省用量优先**：同一难度下，能用 Sol 6.1 解决的不用 astra 6，能用 Luna 6 解决的不用 Sol 6.1。只有赶时间、跨系统、返工或审美要求高时才上 astra 6。
- **argon 先试用再扩大**：先派几次写作 / 文档类任务和一两个小的代码任务，记录结果（基础错误多少、工具是否卡住），结论补在本节下面，再决定代码任务能不能交给它。在有结论之前，argon 写的代码一律由 Codex 或 Claude 复查后才提交。
  - 试用记录 1（2026-10-21，状态说明文案，D2，argon medium）：机制读得准，7 个疑问里有 6 个问到点上，基础错误很少；但两处把持续回合写进了说明（界面已显示），措辞需要统一。用时约 2 分钟。工具层面：`safe` 档位在未信任的工作区连写文件都被拒（exit=4），改成"只在回复里输出、由主对话落盘"后一次通过。结论：写作类可以继续交给 argon；需要它写文件时，用户须先信任工作区或批准 `auto`。
  - 试用记录 2（2026-10-21，讨伐后台词 30 条，D2，argon medium，用时约 4 分钟）：人物口吻和伏笔写得好，还自己发现一个结构问题（部分闲聊在标准流程里不可达，核实属实）。问题：给一个 NPC 编造了背景设定，有一处没考虑玩家性别。结论：剧情文本可以交给 argon，但必须对照剧本做设定核对。
  - 试用记录 3（2026-10-21，050 文案 72 条，D2，argon medium）：参数读得细，还找出 4 个工程问题（追击日志缺名、事件模板、叠毒联动、spell_learned 缺字段）。错误 1 处：把单体法术写成全体，还编了一个不存在的克制关系。结论同试用二：可用，但必须抽查参数。
- **Codex 额度用完**：机械任务改用 Claude Haiku 子代理；常规任务等额度或改用 Claude Sonnet / Opus 子代理；argon 只接写作类。
- **工程任务交给 Claude 子代理**：只在任务很小（几处改动）、Codex 不可用、或需要和主对话判断紧密配合时。
- **审美、风格、“像不像同一个游戏”这类判断**：交给 Claude（Opus 起步），不交给工程执行方；执行方只负责按判断实现。

## 4. 主对话如何把自己的活交出去

| 原本主对话自己做的事 | 现在怎么做 |
|---|---|
| 读长文档、扫代码库找东西 | Explore / Haiku 子代理，只带回结论和文件位置 |
| 看大批截图做审阅 | Sonnet / Opus 子代理分批审，按审阅标准写问题单；主对话只看汇总，并抽查几张关键图 |
| 写任务说明 | Sonnet 子代理按主对话定的要点起草；主对话审改后定稿 |
| 审查执行方交回来的结果 | 子代理先读汇报、看 diff、跑检查，列出问题和疑点；主对话据此做决定，必要时亲自看最关键的一两处 |
| 写进度记录、汇总文档 | Haiku / Sonnet 子代理 |

主对话保留：任务拆分、难度评估与分派、接受 / 返工 / 放行的决定、向用户汇报、需要用户拍板的问题。

## 5. 每次派发都要写下的东西

在任务说明开头或派发记录里写一行：

```
难度 D2 · 执行方 Codex Sol 6.1 medium · 理由：单模块、验收明确，上次同类任务一次通过
```

任务结束后补一行结果：一次通过 / 返工几次 / 用时 / 是否选高了或选低了。连续两次“选高了”就把同类任务降一档；一次“选低了导致返工”就把同类任务升一档。

## 6. 额度与故障

- 某个执行方额度用完：不重试，记录停在哪一步；能换执行方的（同难度的另一家）就换，并在说明里写明“接着上次未提交的改动继续”；不能换的等用户通知恢复。
- 同一任务失败两次：停下来，由主对话重新分析原因，必要时升到 D4 档位（astra 6），或拆成更小的任务。
- 并行规则：同时最多两条工程线；两条线改的文件不能重叠；都要静音、单渲染实例、结束前确认没有残留进程（项目里有这类约束时）。
