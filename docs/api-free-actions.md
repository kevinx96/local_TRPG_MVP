# API 主游玩与自由行动

## 已确定的方向

在线单人和未来的多人体验以 API 为主。本地 Ollama / Koboldcpp 保留配置与适配代码，暂时隐藏，不再作为在线回合的前置步骤或自动降级目标。待有更好的设备和模型时，再独立评估是否恢复。

当前默认 Gemini 3.1 Flash-Lite。密钥继续从本机配置、环境变量或已支持的密钥文件读取，不能写进仓库。个人配置覆盖写在被忽略的 `host/local_config.json`。

## 这一轮实现

- 结构化剧本的自由输入使用一次 API 调用，解释为已有动作、场景交互、对话、澄清或暂不支持。模型不提供资源变化、难度、奖励或目的地。
- 按钮 ID 直接进入原行动引擎。字词相似度只提供候选，不再自动执行动作。自由输入即使与按钮文字完全相同，也经过意图解释，保留疑问、否定和条件语义。
- 新的交互规则支持观察、投食诱导、潜行、准备掩护和使用自我治疗道具。对象性质在剧本中定义，规则可用于新增对象，无需列举每种玩家措辞。
- 程序在副本中校验并执行交互，成功后提交真实状态；对象、物品或目的地无效时，不提交资源消耗或事件。
- 普通聊天不再累计三次后封锁。对话不会直接改变资源和剧情标记；NPC 长期承诺与关系系统尚未实现。
- Semi 中已有结果文本直接展示。自由输入解释为已有动作时，复用原行动引擎和结果文本，不再追加一次叙述请求。Full 中部分按钮行动仍可调用一次叙述 API。
- 默认单次模型尝试、15 秒连接/读取超时；自由行动不再连试其他模型。超时不是精确的整个 HTTP 回合硬截止时间。
- 结构化输出使用 Gemini 的 `responseJsonSchema`；语义正确性仍需真实模型评估。[接口说明](https://ai.google.dev/api/generate-content#v1beta.GenerationConfig)
- 探索骰子改由 Host 产生，浏览器只展示返回的点数。保留 `roll_dice(..., client_rolls=...)` 作为内部测试接口，HTTP 回合不采用客户端点数。
- 场景上下文按完整字段裁剪，保留当前地点，不再截断 JSON。已结算动作使用短叙述 contract。
- 修复 `1d20+2` 数值修正、未知属性静默归零、属性名称不一致，以及 Ignis 胜利后仍可继续攻击的问题。

## 森林入口试玩

新建“紅き邪竜イグニス”的 Base 或 Hybrid 游戏，进入闇の森入口。每名可选角色新增两份携带食。

可输入以下内容；它们是试玩例子，不是关键词菜单：

| 输入 | 程序应有的结果 |
|---|---|
| スライムを攻撃しない | 不启动战斗 |
| 携帯食を投げてスライムを引きつけ、戦わずに通り抜ける | 消耗一份食物、通过道路；敌人未死亡，无击杀奖励 |
| 茂みに身を隠して通り抜ける | Host 潜行判定，消耗 1 SP；失败增加警戒，仍可换方法 |
| 近くの枝で足止めの罠を準備する | 保存一次准备效果，下次潜行难度降低 3；不宣称敌人已被困住 |
| スライムの様子を観察する | 提供可见性质及方法提示 |
| 薬草で自分の傷を手当てする | 按实际缺少的 HP 回复并消耗药草；满血不消耗 |

诱导但未通过时，下一次潜行可免判定通过；开始战斗会清除这次分心和准备效果。成功通过之后记录“已知通路”和解决方式，再次回来可沿通路前进。不会把暂时分心永久解释成敌人死亡。

`scene_changes` 按地点和障碍保存观察、警戒、准备及解决方式。变化附带角色与来源事件；这是未来多人规则的基础，当前仍只有一个可控角色。

**旧存档内嵌旧版剧本，不自动注入新道具或替换剧情。试玩新增森林机制需要新建游戏。** 原存档可继续加载。

## 验证

```powershell
python -m unittest discover -s tests -q
node --check client/app.js
```

付费 API 验证显式开启，最多十条输入，测试存档写入 `.tmp-test`：

```powershell
python -m scripts.evaluate_free_actions --live
python -m scripts.evaluate_free_actions --live --case prepare --case explicit_attack
```

首次真实 API 验证为 8/10；根据失败响应澄清目标与材料的字段说明后，同一开发样例复测为 10/10。复测回合约 1.42–5.13 秒，中位约 2.31 秒。网络调用是真实 API，规则骰点固定以比较路径。这些是小样本开发验证，不是独立测试集准确率或长期战役可靠性结论。

## 后续工作

新增交互性质目前先覆盖森林入口。其他有结构化动作的地点支持 API 理解原有动作与对话，尚未具有完整的环境即兴规则。没有动作定义的旧式导入剧本保留旧兼容流程。

下一阶段扩展到社交、线索与关系记忆，再实现多名角色、房间成员、行动顺序、请求去重和事务保存。当前 JSON 存档仍不适合多人并发写入。

如需恢复本地推理，在个人配置中明确设置 `archived_backends: []`、选择本地后端，并重新评估提示、结构化输出与实际延迟；不应只取消隐藏就承诺同等游戏体验。
