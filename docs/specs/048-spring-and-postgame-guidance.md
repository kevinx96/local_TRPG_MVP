# 048 精霊の泉整改与斩杀邪竜后的指引

来源：用户（2026-10-20，原话摘要见 `docs/design/skills-v2-user-draft.md` 末尾"其他要求"）：
1. 精霊の泉要整改：休息过后应直接前进，或者自动休息再前进，那里游玩体验有很大问题。
2. 通关（斩杀邪竜）后缺乏指引：推进主线的选项改成醒目的金色；回城后不应再问邪竜弱点等，已斩杀的敌人相关问题直接隐藏，或让城中对话按是否斩杀邪竜出现不同选项。

另有一条设计约束：`docs/design/balance-v2-decision-metrics.md` 的 B4 与 5.2——**不得存在"免费回满 + 可重复战斗"的循环**（零成本刷级），精霊の泉的限制必须在 EXP 改动上线前就位。

## 0. 文件边界与顺序
- **在 047 完成之后进行。**
- **可以改**：两份剧本包（`dragon_rpg.json`、`dragon_rpg_hybrid.json`，**始终同步**）、新增迁移脚本 `scripts/scenario/spring_postgame.py`（**必须幂等**，测试检查重跑不改变剧本）、`client/`、`host/` 中与选项显示 / 可见性相关的部分、`host/prompt/processed/scenario_pack.schema.json`、`tests/`。
- **不得改**：`scripts/balance/`、`eval/benchmark/`、提示词措辞（`gm_contract.py`、`free_actions.py`）、任何敌人 / 道具 / 商店数值字段（047 的冻结快照必须保持通过）。
- 本任务的改动是**流程与可见性**，不是数值，所以对 baby 与 normal **同样生效**；汇报里写明对 baby 玩家体验的影响（精霊の泉只能休息一次）。

## 1. 精霊の泉

### 1.1 现状（工程动手前先核对，不一致就在汇报里说明）
- 地点 `elf_spring`：行动 `rest_at_elf_spring` 先 `restore_full`，随后在没有 `defeated_slime_king` 时进入 `slime_ambush_one` → `slime_ambush_two` → `slime_king_battle` 三场战斗，全部胜利后回到 `elf_spring`；已有 `defeated_slime_king` 时休息只回满、没有战斗。
- 因此：第一次休息要打三场（斩杀后掉鉄壁の霊薬、金币 +75），之后可以**无限次免费回满**；休息后必须自己再点一次"休まず先へ進む"，体验断裂。
- 同一地点还有：`continue_from_elf_spring`（去 `forest_wolves`）、`inspect_spring_wall`（去 `cave_seal`）、`spring_back`（回十字路）、`draw_spirit_spring_water`、泉の精霊の声（信仰判定）。这些保持不变。

### 1.2 两个方案（实现其一）

**方案 A（推荐）：休息一次，打完自动前进，泉只能回满一次。**
- `rest_at_elf_spring` 加 `once` 标记（例如 `rested_at_elf_spring`），一次之后该选项永久隐藏。保留回满与三场战斗（对应原设计：休息被打断，是这段的叙事和资源代价）。
- `slime_king_battle` 胜利后的去向从 `elf_spring` 改为 `forest_wolves`（和"休まず先へ進む"同一目的地），在 `victory_effects` 里直接前进；胜利叙述文本沿用现有 `result_texts`，并在末尾接一句过渡台词（**占位**，见第 3 节）。
- 已完成斩杀 / 休息过的玩家之后再回到泉：只剩前进、岩壁、十字路、汲水、聆听这几项。
- 玩家主动"休まず先へ進む"的路径不变（不休息、不打史莱姆王，鉄壁の霊薬拿不到，这是玩家的选择）。
- 其他仍然提到"回到泉休息"的文本或提示（`preview`、`risk`、洞窟入口附近的说明、`fallback_choices`）要同步，不能再暗示可以反复休息。
- 对原有"休息不会再有战斗"分支（`branch` 里 `defeated_slime_king` 的 `then: []`）：因为休息只会发生一次，这个分支变成死代码；清掉它，但要确认旧存档（已经 `defeated_slime_king`、位于 `elf_spring`）仍然能玩——这类玩家看不到休息选项，也不会卡住。

**方案 B（不推荐）：自动休息再前进，不打史莱姆。**
- 把"休息"并入前进：进入泉时回满一次，不再触发三波史莱姆，史莱姆王变成可选内容或移除。
- 不推荐的原因：史莱姆王是教学 Boss（掉鉄壁の霊薬、金币、`defeated_slime_king` 被下游使用），去掉会改变奖励、等级里程碑与若干 flag 的来源，波及面大。

### 1.3 零成本刷级检查（两个方案都要做）
- 写一个审计测试 / 脚本：遍历两份剧本里所有**可重复**（没有 `once` / `disabled_after`）且能回复资源的行动（`restore_full`、`restore_ratio`、回复类 `effects`），列出它们，并检查它们是否位于一个"之后可以无限触发战斗"的环里。
- 结论写进汇报：除精霊の泉外还有没有免费回满 + 可重复战斗的环。**发现其它环时不要擅自改**，列出位置和建议，由设计负责人决定。

## 2. 斩杀邪竜后的指引

### 2.1 flag 与范围
- "斩杀邪竜"在剧本里的标志以剧本为准，工程去查并在汇报里写明。我读到的情况：`dragon_valley_loc` 战斗胜利时设置 `defeated_ignis`；圣水净化路线则设置 `ignis_purified` 并进入 `ignis_purified` 地点，不经过 `defeated_ignis`。**默认处理**：本节所有"已讨伐"判断用 `defeated_ignis` **或** `ignis_purified`（两条路线的邪竜都不再是威胁，弱点之类的问题同样过时）；若你查到的事实不同，按事实处理并说明。
- 主线推进选项的"金色"只在**斩杀（或净化）邪竜之后**使用，范围是从 `ignis_last_breath` / `ignis_purified` 起到结局的路径。邪竜之前的主线不动。

### 2.2 数据与渲染
- 行动数据增加布尔字段 `guidance: true`，表示"推进主线的指引选项"。同步更新 `scenario_pack.schema.json`，并保证该字段会出现在发给客户端的选项对象里（核对选项构造路径：`public_session`、`scenario_context.current_action_choices`、前端读取处）。
- 客户端统一渲染：金色按钮样式（使用 `client/styles.css` 的主题变量，浅色 / 深色都要对比度足够），并加一个非颜色的标记（例如左侧小星标），不能只靠颜色区分。键盘焦点、悬停、禁用状态都要正确。
- 客户端不做任何"判断哪个是主线"的逻辑，只看 `guidance`。
- 提示词和模型上下文**不动**：`guidance` 不进入给模型的内容（核对 `scenario_context`，如果它按白名单序列化行动字段则自然满足，否则排除并加测试）。冻结 benchmark 重放 194/194 不变。

### 2.3 要标记的选项
斩杀 / 净化邪竜之后，沿主线推进的行动，起步清单（工程补全并逐项列进汇报）：
- `castle_report` 的「討伐を報告する」`report_normally`、「将軍ドラコの正体を問いただす」`report_with_evidence`（若可见）；
- `festival_town` 的「凱旋の間へ向かう」`go_report_hall`、满足条件时的「将軍の屋敷へ向かう」「国王に内密の謁見を願い出る」；
- `ignis_last_breath` / `ignis_purified` / `dragon_valley_return` / `royal_gate` 一路上推进回城的行动；
- 之后到结局的每一步里真正推进主线的那一个（分叉处每个分支各标一个）。

### 2.4 隐藏过时选项，并让城中对话按讨伐与否分化
- 隐藏条件用现有的 `hidden_after`（flag）/ `requirements`（含 `any` / `not_flag`）表达，不新增条件类型，除非现有无法表达。
- 起步清单（已在剧本里确认存在，工程补全）：
  | 地点 | 行动 | 处理 |
  |---|---|---|
  | `castle` | `ask_king_info`「国王に邪竜の詳しい話を聞く」 | 讨伐后隐藏，换成讨伐后的对话选项（占位） |
  | `castle` | `ask_general_advice`、`ask_king_ten_years` | 检查是否仍有意义，讨伐后按需隐藏或换文 |
  | `forge` | `ask_blacksmith_weakness`「邪竜を討つ方法を聞く」 | 讨伐后隐藏；换成讨伐后的闲聊（占位） |
  | `magic_shop` | `ask_blue_mage_rumor`「邪竜についての噂を聞く」 | 讨伐后隐藏；换成讨伐后的闲聊（占位） |
  | `village` | `talk_elder`；`village_frozen_clue` / `ian_ice_katana_aftermath` 的 `visit_village`「長老に邪竜の弱点を聞く」 | 讨伐后隐藏 / 换文 |
  | 其他 | 凡文本含「弱点」「討伐方法」「討伐の相談」或设置 `heard_dragon_weakness` 等邪竜前线索 flag 的选项 | 全量搜索，逐项列出并处理 |
- 注意这些地点（`forge`、`magic_shop`、`castle`）在邪竜前后是**同一个地点**，所以必须靠 flag 区分，不是拆地点。
- 王都（`castle`、`castle_town`）和凱旋の城下町（`festival_town`）里的 NPC 对话：每个 NPC 在"未讨伐 / 已讨伐"两种状态下各自应该给出什么选项，工程**先列一张表**（NPC、地点、未讨伐选项、已讨伐选项、需要的新台词数），再实现。已讨伐的新选项，数据结构照现有对话行动（`npc_id`、`once`、`result_text`），已讨伐的对话不应设置会影响结局判定的 flag（除非表里明确要求，并在汇报里说明）。
- 隐藏后必须保证每个地点至少还有离开的选项，不会卡死；加测试遍历"讨伐后"的所有地点，断言每个地点至少有一个可见选项。

## 3. 台词：占位并列表（台词由设计负责人提供）
**不要自己写最终台词。**需要新增的日文文本一律写成占位，统一前缀 `【仮】`，并且：
- 每条占位文本控制在一句以内，只表达功能（例如「【仮】泉でのひと休みを終え、先へ進む。」），不做文学润色；
- 在汇报里列一张表：文本位置（地点 / 行动 ID / 字段）、用途、出现条件、现在的占位原文、建议长度；
- 加测试：所有 `【仮】` 文本都能被统一搜索到，数量等于汇报表的行数（设计负责人补写定稿后，会删除前缀；测试在那时再改）。
预期占位类别：泉的过渡台词（方案 A）；讨伐后 NPC 对话（国王、将軍、侍従 / 店主们、长老等，数量以第 2.4 节的表为准）；换文后的闲聊选项名称。选项文字（按钮上的字）同样用 `【仮】` 前缀。

## 5. 验收与汇报
- 单元测试：
  - 泉：第一次休息进入三场战斗并以前进到 `forest_wolves` 结束；休息选项之后不可见；未休息的玩家仍可"休まず先へ進む"；旧存档（已斩杀史莱姆王、在泉）不卡住；

## 设计负责人决定（2026-10-20）
- 精霊の泉采用**方案 A**：只能休息一次，休息后的三场伏击打完自动前往 `forest_wolves`，泉不再能回满。这是体验修正，baby 也生效。
- "已讨伐邪竜"包括 `defeated_ignis` 和净化路线 `ignis_purified` 两种；隐藏过时选项和金色指引都按这两个 flag 之一判断。
- NPC 讨伐后的台词：工程先列出 NPC 对话表，并用 `【仮】` 占位实现；最终台词由设计负责人另行提供（交给写作执行方起草后审定），不在本任务内。
