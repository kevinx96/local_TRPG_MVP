# 013 イグニス净化路线

按 `docs/design/scenario-v2.md` 第 6 节实施，日语正文**逐字使用**，两份剧本同步修改。

## 1. 引擎
1. **条件型战斗行动**：遭遇可以声明 `special_actions`。每个特殊行动带有：显示条件（requirements，加上"敌人 HP 比例 ≤ x"）、费用（消耗某件物品或者 MP）、效果（以指定结果结束战斗并应用 effects）、战斗日志文。条件不满足时，这个行动不出现在 `combat_actions` 里。写测试：条件全部满足、缺任意一个、HP 还在阈值以上。
2. **以非胜非败的结果结束战斗**：例如 `purified`。不发击杀奖励，也不设置 `combat_defeated:*` 这类 flag；执行行动自己的 effects，然后正常收尾，回到探索。
3. **二阶段援军**：遭遇或阶段可以声明 `phase_allies`。条件满足时（例如 flag `ignis_ally`），进入该阶段时追加一段文字，并在每回合开始时执行援军的效果（例如对敌人造成火属性伤害）。援军不能被攻击，也不会倒下。如果现有的同伴 round_start 机制可以复用，就复用。写测试。
4. 任务阶段的 `done_flag` 支持数组（满足任一即可）。

## 2. 剧本数据
- 6.2 的两个特殊行动，6.3 的新地点和动作，6.4 的援军和两个新结局，6.5 的任务变化。
- `heard_ignis_testimony` 加进揭发条件的线索 flag 列表（scenario-v2.md 3.5）。
- `key_items.json` 和 `redundancy.py`：把净化的"知道条件"和"手段"作为两项新的关键资源，每条路线上要求各至少 2 个来源。

## 3. 数值
- 按 6.6 设定イグニス援军的伤害，并做模拟：净化路线（有援军）ドラコ战胜率 [0.65, 0.80]，击杀路线不变（[0.50, 0.70]）。
- 模拟 heuristic 策略：条件满足、并且持有手段时，在 HP ≤ 40% 后优先净化。报告"打到可以净化"所需的回合数，和"直接打倒"对比。
- `targets.json` 加上净化路线的目标；route 模拟加一条"净化 → 真结局"路线（只报告）。

## 4. 测试（剧情可达性）
- 净化：两种手段（聖水、僧侣祈祷）× 每个"知道条件"来源（每个来源单独测）都能出现特殊行动；没有知识、没有手段、HP 在阈值以上时都不出现。
- 净化后：必定能拿到白い竜鱗，揭发一定成立；有/没有 `ignis_ally` 分别得到对应的结局；净化后正常汇报，得到 `ignis_purified` 结局。
- 击杀路线的所有原有测试不受影响。
