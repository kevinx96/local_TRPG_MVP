# 027 连续流程模拟：按职业选择路线

## 背景
022 以后，在会付费休息的策略（hp70）下，主线通关率是 勇者 59% / 僧侶 49% / 魔法使い 55% / 盗賊 40%（`eval/reports/balance-2026-10-12-ch34c.md`）。但模拟走的是**固定路线**：每个职业都战斗突破 D1（谷口）、走吊桥、放弃リク等。真实玩家会按职业选择更有利的选项（敏捷高就潜行，带着冰属性道具就用冷气灭火）。设计原则是"每种选择都能通向胜利"，所以通关率应该在"合理的选择"下衡量。

## 要求
1. 在 `scripts/balance/route.py` 新增策略 `class_aware`（和现有的 `none`、`hp70` 并列，叠加在 hp70 的休息规则之上）：
   - 每个可以用判定代替战斗、或者有多种通过方式的节点，计算各选项的**期望结果**，选最好的那个：
     - 判定选项：成功率 = P(1d20 + 属性修正 ≥ DC)，失败的后果按剧本数据推算（开战、敌人先手、扣 HP 等）
     - 战斗选项：用现有模拟器在当前资源下估算胜率（可以先用小 N 估算，再缓存）
     - 免判定选项（例如持有冰属性道具时的「冷気で炎を鎮める」）直接视为成功
   - 选择依据只能是**玩家在游戏里看得到的信息**（选项文字、显示出来的判定、角色属性、背包），不能读取随机数结果。
   - 支线（救リク、ガルド等）：只要不会显著降低通关率（期望损失 < 2pp）就去做，模拟"愿意探索的玩家"。
2. 报告 `eval/reports/balance-<日期>-class-aware.md`：三种策略（none / hp70 / class_aware）× 四职业的主线通关率、失败地点分布，以及 class_aware 在每个分支点的选择统计（各职业选了什么、选择次数）。
3. 判定：主线目标 [0.55, 0.90] 按 `class_aware` 评价。达不到时，列出卡在哪里、还差多少，不要改任何剧本数值。
4. 测试：策略不读取随机数（固定种子下，策略的选择只依赖可见信息）；期望值计算的单元测试；三种策略都能跑完。

## 不做
不改剧本、不改目标、不改提示词。

`python -m unittest discover -s tests -q` 和 `node --check client/app.js` 通过；报告齐全。完成后提交到当前分支，提交信息以 `[工程]` 开头，只 `git add` 具体文件。
