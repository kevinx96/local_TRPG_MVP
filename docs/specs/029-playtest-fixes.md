# 029 试玩问题修正（状态一致性、死路、叙述缺失、文本不符）

来源：设计负责人的自动试玩（4 职业 × 多个种子，离线、无 LLM）和一次现场试玩，2026-10-13。在 028 的基础上做。两份剧本始终同步修改。下文的日文叙述是定稿文本，照抄。

## 1. 状态一致性和死路（最优先）

### 1.1 ゴブリン砦可以重复进入，第二次在财宝庫卡死
复现：从宿屋接下ロビンの依頼 → 打通砦 → 回到十字路接下迷子のゴブリン的请求 → 「ゴブリン砦へ向かう」→ 再走一遍。到 `goblin_fort_fourth` 时王已经死了，没有战斗也没有任何剧本选项，只剩通用兜底选项，游戏卡死（8 次试玩里 3 次）。
- 砦打通后（以ゴブリン王击败为准），所有进入砦的选项（宿屋的 `accept_robin_goblin_quest`、十字路的 `enter_goblin_fort`）都隐藏。
- **通用规则**：玩家在任何状态下到达的任何地点，都至少有一个剧本选项可选（不能只剩通用兜底选项）。用第 4 节的试玩脚本作为回归测试。

### 1.2 迷子のゴブリン的三种状态
- 在十字路选「無視」被他偷袭并杀死后：十字路不再出现「箱を取り戻す手伝いを引き受ける」和「無視」；砦里打完ゴブリン王后，他不再「現れ」，`goblin_fort_chest_choice` 只剩一个选项「箱を持ち帰る」（拿到箱里的东西，不战斗），叙述：

- 经ロビン路线先打通砦并且已经还箱或抢箱后：十字路不再出现他和他的请求（他已经回森里或已经死了）。
- 没见过他、经ロビン路线到财宝庫时他第一次出现，这个保持原样。

## 6. 从区域入口重来（用户已确认）
战败导致游戏结束时（不是剧情结局、不是 scripted_loss），结束画面除了「新しい冒険」外再给一个「このエリアの入口からやり直す」。
- **区域**：死亡地点所在的地图（`maps` 里 `location_ids` 包含该地点的那张）。不属于任何地图的地点，以最近一次地点变化为准。
- **入口快照**：每次从地图外进入某张地图的任一地点时，保存一份游戏状态快照（覆盖该地图上一次的快照）。快照包含全部游戏状态（角色、背包、金币、flag、地点、同伴、任务、里程碑、已访问地点、商店库存等），不包含 `scenario_pack`、消息、日志、骰子记录、trace。具体包含哪些字段在汇报里列出。
- **重来**：恢复快照，清除 `game_over` 和战斗状态；消息记录保留，追加一条 GM 叙述（`{area}` 用地图标题）：
  > 運命の糸がほどけ、あなたは再び{area}の入口に立っていた。
  并在系统日志记一条「{area}の入口からやり直しました。」。session 里累计重来次数（`retry_count`），trace 里也记一笔，供研究统计。
- 恢复的是进入时的原样（不回满 HP）。如果试玩脚本发现「入口快照的状态下必死、又无法离开」的循环，列进汇报，不要自己改数值。
- 第 5 节的试玩脚本：死亡时先重来一次再继续，报告里分别统计「首次死亡」和「重来后的结果」。
- 客户端：按钮样式沿用结束画面现有按钮；文案「このエリアの入口からやり直す」。
- 测试：快照在进入地图时生成、重来后状态与快照一致、剧情结局和 scripted_loss 不出现这个选项。
