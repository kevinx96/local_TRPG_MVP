# 040 判定 v2：技能名、D&D 式修正值、优势/劣势

来源：用户（2026-10-19）：提高 D&D／TRPG 感；专长职业的判定几乎稳过，骰子没意义。设计全文和数值依据见 `docs/design/checks-v2.md`，本 spec 只写要做的事。两份剧本同步修改，日文为定稿文本。依赖 039（判定卡和动画）已完成。

## 1. 修正值（D）
- 非战斗判定（选项的 `roll`、自由行动的潜行，以及第 4 节以后会加的观察判定）改用：
  修正值 = max(0, ⌊(属性 − 10) ÷ 2⌋) ＋ 熟练加值（Lv1–3 为 +2，Lv4–5 为 +3；只在该技能属于职业熟练时加）。
- 战斗技能里的 `check` **不变**。
- 039 的判定卡数值和实际掷骰仍由同一个函数算出。

## 2. 技能名（B）
- `roll` 增加 `skill` 字段（技能 id 用日文名即可，如 `隠密`）；属性由技能决定（`docs/design/checks-v2.md` 第 3 节的表）。
- 职业熟练表放在剧本数据里（每个可选角色一项），不要写死在代码里。
- 29 个判定按设计文档第 5 节分配技能和档位；DC 分档 易 8、中 10、難 12、至難 14；DC999 的 3 个不变。
- 自由行动障碍的 `sneak_dc`（现为 14）改为 隠密・中。
- 选项的风险文字改为 `隠密（敏捷）判定・DC10`，有 SP 消耗的保留「・SP1消費」。判定卡第一行改为 `隠密（敏捷）判定　DC 10`，第二行 `1d20 ＋ 5（敏捷＋熟練）`。
- 写一个幂等的迁移脚本（`scripts/scenario/checks_v2.py`），像以往一样由测试检查重跑不改变剧本。

## 3. 优势/劣势（C）
- 掷 2 颗 d20，优势取高、劣势取低；两者同时成立则抵消，只掷 1 颗。
- 来源（详见设计文档第 4 节）：
  - 现有 `dc_overrides` 的两个条件改为给优势，DC 回到档位值；
  - 自由行动 prepare：对该障碍的下一次潜行有优势（替换原来的 DC−3）；
  - 同伴协助：同伴在队时对应技能有优势（表在设计文档里，放进同伴数据）；
  - HP 不到最大值 25%：運動・軽業・隠密 有劣势，理由「傷が痛む」；
  - 现有"潜行失败后警戒上升"如果是加 DC，改成对该障碍的下一次潜行有劣势，并在汇报里说明原来的机制。
- 039 的 `check` 字段增加 `advantage`（`"advantage"`／`"disadvantage"`／`null`）和 `advantage_reasons`（日文短句数组，如 `["ロビンの助言"]`、`["封印の知識"]`、`["傷が痛む"]`）。
- 判定卡显示「有利：ロビンの助言」或「不利：傷が痛む」；动画掷两颗骰子，被采用的那颗高亮，另一颗变暗。
- 骰子日志里记录两颗的点数和采用的那颗。

## 4. 观察判定与通用的优势条件（为设计负责人后续的剧本改写准备）
- 场所 `objects` 已有的 `observe_reveals.roll`（6 个带属性的）同样改用 v2：
  | 对象 | 技能 | 档 |
  |---|---|---|
  | castle / general_breath | 知覚 | 難 |
  | elf_spring / small_footprints | 知覚 | 易 |
  | goblin_fort_third_gate / iron_gate_window | 知覚 | 中 |
  | ice_elemental_encounter / frost_crystal | 知覚 | 中 |
  | cave_seal / seal_glyphs | 魔法学 | 中 |
  | valley_lava_bridge / bridge_ropes | 知覚 | 易 |
  `dice_type: "none"` 的保持不掷骰。039 的判定卡不用于观察（自由输入事先不知道判定），走短版动画。
- `roll`（选项和 `observe_reveals` 都适用）支持通用的 `advantage` / `disadvantage` 条件列表：`[{"requirements": {...}, "reason": "封印の知識"}]`，满足 `requirements` 就加上对应的优势或劣势和理由。第 3 节的线索优势就用这个字段写进剧本数据；同伴、准备、HP 这些通用来源仍由引擎判断。
- 本任务**不新增任何判定**，只做机制、转换和测试；新的判定由设计负责人后续编写。

## 4b. 039 的遗留
- 039 汇报的 TODO(design)：`critical_enabled: false` 的行动，自然 1／20 **只显示点数**，不显示「大成功／大失敗」，也不播放极值特效；成败行照引擎实际结果。
- 判定卡里的「成功」「失敗」文字分别用现有的绿色／红色（同骰子横幅的 success／failure 配色）。

## 5. 不做什么
- 不改战斗、不改 prompt、不改剧情文本，不新增判定（新增判定由设计负责人另行编写）。
- 不碰 `eval/benchmark/`、`docs/`。
