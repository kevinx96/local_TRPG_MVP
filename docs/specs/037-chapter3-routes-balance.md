# 037 第三章三条路线的联合平衡、试玩数据、手机战斗布局

033–036 完成后，第三章有三条路线：麓の村（主线）、霧の古戦場（031）、地鳴りの峡谷（035，经オークスドーン）。本 spec 把它们放在一起看。

## 1. 连续路线平衡
从第 2 章结束可达的检查点出发，一直模拟到イグニス战结束（胜 / 败），4 职业，每组 N≥2000。
- 路线 × 条件：
  | 路线 | 条件 |
  |---|---|
  | 村 | 无同行者 / ワーロック / 火コウモリ竜 |
  | 古戦場 | 无 / リーゼ；无诅咒 / 有诅咒 |
  | 峡谷 | 无 / エリオ |
- 进入古戦場 / 峡谷之前在オークスドーン可以做的准备（聖銀武器、鎖帷子、休息）按「做了」和「没做」各跑一组。
- **目标**：
  - 每个职业，三条路线（无同行者）到イグニス的通关率，任意两条相差 ≤ 8pp。
  - 每条路线的对策同行者（古戦場=リーゼ、峡谷=エリオ）在本路线上的提升 ≥ 其他同行者在该路线上的提升。
  - 没有哪条路线对四个职业都是最优。
- 只允许调 033–035 新增内容的数值（新敌人、新 DC、リーゼ／エリオ、新装备、新奖励金币）。现有内容一律不动。达不到时停下来报告，由设计负责人决定。
- 报告 `eval/reports/balance-2026-10-18-ch3-routes.md`。

## 2. 试玩数据（给攻略书用）
- `python -m scripts.playtest.explore`：4 职业 × 8 个种子（20261013、20261014、101–106），每局最多 250 步，离线。探索策略在第 2 章出口三条路线之间按种子轮换优先（保证三条路线都有足够样本），其余保持现行策略。
- 输出 `eval/reports/playtest-2026-10-18-ch3/`：逐局日志，以及汇总 JSON / Markdown：
  - 结局分布、首次死亡地点、重来次数。
  - 每局走了哪条第三章路线、带了哪个同行者、拿了哪些真结局线索（列出 flag）。
  - 通关局之间的选择重合率（Jaccard，按「地点 + 选项」，去掉纯移动）和到访地点重合率，均值 / 最小 / 最大。
  - 每条线索被多少局拿到；从未被任何一局到达的地点。
- 不变量：异常、非战斗死路、兜底叙述为 0。

## 3. 手机竖屏的战斗布局（036 汇报的已知问题）
宽度 < 768px 时：
- 敌人区域放在最上方、占满宽度，立绘高度不低于视口高度的 28%。
- 玩家卡片改为一行紧凑条：小头像（40px）＋ 名字 ＋ HP / MP / SP 三条进度条。
- 战斗日志默认只显示最新 3 行，点一下展开全部。
- 行动按钮放在底部，两列网格；标签页（攻撃 / 技能 / 道具 / 戦術）保持一行。
- 动画（030）在这个布局下照常；`prefers-reduced-motion` 照旧。
- 只用现有样式变量；缺的留 `TODO(design)`。
