# 011 观察对象修正 + 剧本 v2 补充 benchmark

## 背景（设计负责人用 Gemini 实测）
| 地点 | 输入 | 结果 |
|---|---|---|
| castle | 将軍ドラコの様子をじっと観察する | plan `observe target=general`（NPC 的 id），引擎找不到对象，回复"请指定观察对象"。**失败** |
| castle | 将軍の足元に何か変わったところがないか見る | 同上，**失败** |
| goblin_fort_third_gate | 鉄門の小窓に耳を当てて、中の声を盗み聞きする | 正确，但成功文「入手した暗号で鉄門を開ける。」读起来像已经开了门，实际玩家还在门外 |
| ice_elemental_encounter | 路地に散らばっている氷の結晶を調べる | 正确 |

这些成功和失败的文字，是设计负责人在 scenario-v2.md 里漏写的，下面补上。

## 1. 文字（逐字使用，两份剧本同步）
| 对象 | description | success_text | failure_text |
|---|---|---|---|
| `general_breath` | 国王の傍らに立つ将軍ドラコ。穏やかな表情で広間を見渡している。 | 将軍の足元だけ、絨毯にうっすらと霜が降りている。（不变） | 将軍は穏やかに微笑んでいる。特に変わった様子は見えない。 |
| `iron_gate_window` | 四階へ続く鉄門の小窓。中から見張りの話し声が漏れている。 | 小窓の奥で、見張りが合言葉を小声で繰り返している。どうやら、これが鉄門の暗号らしい。 | 中の声はくぐもっていて、言葉までは聞き取れなかった。 |
| `frost_crystal` | 凍った路地に散らばる、溶けない氷の結晶。 | 溶けない氷のかけらを一つ拾い上げた。指先がじんと痺れる。 | 拾おうとした結晶は、触れた瞬間に砕けてしまった。 |

## 2. NPC 的 id 对应到观察对象
- 对象可以声明 `npc_id`。observe 的 `target_id` 是当前地点某个 NPC 的 id、并且有对象声明了这个 `npc_id` 时，按该对象处理。
- 给 `general_breath` 加上 `npc_id: "general"`。
- 写测试：用 NPC 的 id 和用对象的 id 观察，结果完全相同；没有对应对象的 NPC，行为保持不变。

## 3. 补充 benchmark 候选：`eval/candidates/intent_v2_scenario.jsonl`（拟定）
覆盖剧本 v2 新增的交互点，格式和 v2 相同（gold、harmful、family、split），按 `eval/benchmark/LABELING.md` 标注。**逐条手写**，40–60 条：
- 快照（新建）：王城（出发前）、三階鉄門、氷の精霊、紅竜の最期、凱旋の間（有证据 / 没有证据各一个）
- 标签（每类至少 6 条）：
  - `observe_clue`：用各种说法观察将军、小窗、结晶、イグニスの傷
  - `report_choice`：凯旋时选择揭发或正常汇报，包括"先别说出来"这类说法
  - `evidence_claim`：没有证据却自称"有证据，将军就是白竜"（应该 unsupported 或 dialogue，不能触发揭发；揭发是有害误触发）
  - `scale_handling`：对白い竜鱗的各种自由处置（给国王看、拿去问将军、扔掉），按引擎能支持的动作标注
  - `lore_question`：在长老、イアン那里打听盟约和白竜
- 这批用例是给剧本 v2 的回归测试，不并入冻结的 test split。
