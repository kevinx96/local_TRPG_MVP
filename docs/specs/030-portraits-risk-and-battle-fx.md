# 030 立绘切换时机、探索的风险标签、战斗动画

来源：用户试玩反馈 + 设计负责人试玩（2026-10-13）。两份剧本始终同步修改。

## 1. 展开父选项时就切换立绘
现在在宿屋和ロビン说完话后点「イアンと会話する」，要等选了子选项才换成イアン的立绘。
- 点开带 children 的父选项时立即切换说话人立绘：用父选项的 `portrait_image`；父选项没有、而所有带立绘的子选项是同一张时，用那一张。收起或返回上一级时恢复原来的立绘。
- 数据：同一 NPC 名下的子选项缺 `portrait_image` 的，补成父选项的（例如「竜と人の昔話を聞く」→ イアン，「将軍の部屋から盗んだ物を見せてもらう」→ ロビン）。写测试：父选项有立绘时，子选项要么没有、要么和父选项相同；有例外就在汇报里列出。

## 2. 探索未知地点不提前给出风险
砦二层的分岔口现在显示「右の通路を探索する｜判定不要」「左の通路を探索する｜危険（戦闘）」：标签直接告诉玩家哪边打架。而且右边也会碰到大ゴブリン，「判定不要」反而误导。
- **规则**：在第 1 章城下町以外的地图里，**移动到还没到过的地点**的选项，risk 显示「不明」（用现有的中性标签样式）。到过以后显示真实标签。
- 动作本身的判定（例如「見張りを迂回する｜1d20+dex判定（DC13）」）和**当前场景里已经看得见的敌人**（「見張りのゴブリンと戦う｜危険（戦闘）」）不受影响，照常显示。
- 要判断的是：这个选项的风险来自**目的地**（进入后开战、目的地的遭遇），还是来自**动作本身**。前者算「不明」，后者照常。在 `scripts/scenario/risk_labels.py` 一侧实现，引擎按 session 的已访问地点决定显示哪个。分类结果在汇报里列表。
- 场景描述里的提示（「左から獣の唸り声」）保留，这是给玩家的线索。

## 3. 地点的 enemy_ids 和实际遭遇一致
`goblin_fort_second_left` 的地点 `enemy_ids` 是 5 只 war_hound，实际战斗（`combat.enemy_ids`）只有 1 只。地点的 `enemy_ids` 会作为场景上下文发给 LLM，可能让它描写成一群狗。
- 所有地点：地点 `enemy_ids` 与该地点战斗的 `combat.enemy_ids` 不一致的，改成和战斗一致（战斗是准的）。写测试。改动列表写进汇报。

## 4. 战斗动画
现在战斗只有文字日志。目标：每个行动都能「看」到发生了什么，同时节奏不拖沓。

### 4.1 做法
- **以程序生成的效果为主**（CSS / Web Animations / canvas 粒子），不新增位图素材。现有立绘是厚涂动画风格，像素风特效会和它冲突，所以不用 Aseprite 像素图。
- 引擎在每次战斗行动的结果里给出结构化事件（行动者、目标、命中 / 未命中 / 暴击、伤害或回复量、属性、是否击倒、阶段切换）。现有的战斗日志已经有这些信息的话，直接复用，不要重复计算；客户端只按事件播放动画，不自己推断结果。

### 4.2 每种事件的表现（时长为上限，单位 ms）
| 事件 | 表现 |
|---|---|
| 我方攻击 | 我方卡片朝敌人方向前冲 12px 再回位（160）；敌人立绘白色闪光（80）+ 左右抖动 ±6px（240）；按属性在敌人身上播放命中特效（300）：物理 = 白色斜线斩痕，火 = 橙色火星，冰 = 青色冰片，圣 = 金色光柱，弱点 / 虹 = 七色光环 |
| 伤害数字 | 在目标上方弹出并上浮 30px 后淡出（700）；普通白色，暴击用 `--gold`、字号 1.5 倍并带「CRITICAL」，回复用 `--green` 并带「+」，未命中显示灰色「MISS」且目标横移闪避 8px |
| 敌人攻击 | 敌人立绘朝玩家方向前冲（160）；我方卡片红色闪光（`--red-dim`，120）；伤害达到最大 HP 25% 以上时画面整体抖动 4px（200） |
| 回复 / 增益 | 绿色或金色粒子从目标卡片底部上升（500） |
| HP / MP 条 | 新值在 400ms 内缓动过去；HP 减少时保留一条浅色「延迟条」，再过 300ms 跟上（格斗游戏式） |
| 击倒 | 敌人立绘去饱和、下沉 16px 并淡出（600） |
| 阶段切换（ドラコ人形 → 竜形 等） | 全屏白色闪光（150）+ 抖动（400），立绘交叉淡入新形态（500），日志里阶段切换那句同时出现 |
| 胜利 / 败北 | 沿用现有的结果面板，出现前留 300ms 停顿 |

- **节奏**：一次行动（我方 + 敌方回应）的动画总长不超过 1.4 秒；日志的每一行和对应动画同时出现。点击画面或按空格可以跳过当前动画、直接显示结果。
- `prefers-reduced-motion` 时：不抖动、不前冲，只保留淡入淡出、数字和 HP 条（无延迟条）。
- 颜色只用 `styles.css` 现有变量；缺的留 `TODO(design)`。

### 4.3 无障碍
战斗操作按钮现在没有可读名称（无障碍树里是空的 button）。给每个行动按钮加上「名称＋要点」的 `aria-label`（例：「鉄の剣で攻撃 威力1d8+str/3 命中90%」），伤害数字用 `aria-live` 区域同步播报一行文字。

### 4.4 验收产物
- 录制关键帧：用浏览器脚本对下面每种事件截 3–5 帧（开始、峰值、结束），拼成一张对比图，放到 `eval/reports/screens/030/`：普通攻击、暴击、MISS、火 / 冰 / 圣属性命中、敌人重击（含画面抖动）、回复、击倒、ドラコ阶段切换、reduced-motion 下的普通攻击。
- 另录一段 10 秒左右的 GIF 或 WebM：一场完整的普通战斗（`goblin_fort` 的见张り戦）。
- 截图检查里加上：动画结束后 DOM 状态（HP 条数值、日志行数）和不播放动画时完全一致。
