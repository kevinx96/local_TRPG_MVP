# 042 骰子的质感：手绘 d20 与物理感的掷骰演出

来源：用户（2026-10-19）：039 的 d20 是纯多边形轮廓，和游戏的厚涂画风不搭，有点出戏。本任务只换骰子的外观和动作，判定规则、时长上限和流程（039／040）不变。依赖 040 完成（两颗骰子的优势显示）。

## 1. 美术（imagegen）
- **骰子本体**：一颗 d20，512×512，透明背景，正面朝向观众的那个三角面**留空**（不画数字），其余面可以有隐约的刻纹但不要可读的数字。画风同 036 的道具图标（厚涂、可见笔触、左上光源、饱和度克制）。
- 三种材质，各 2 个候选：
  - A 旧象牙／骨：米白、细裂纹，数字用暗红墨（叠加层的颜色，见第 2 节）；
  - B 深红宝石：半透明的深红，内部有光，数字用金色；
  - C 黑铁：发黑的锻铁，边缘磨亮，数字用银色。
- **大成功／大失败**：每种材质再出一张"裂开"的变体（同角度，表面有裂纹），用于自然 1；自然 20 用 CSS 光效，不另画。
- **托盘**：一张俯视的圆形骰盘，深色绒布＋木框，800×400 左右，透明背景，画风同上。
- 全部放 `assets/candidates/042/`，登记 manifest（`approved: false`），做一张总览图 `eval/reports/screens/042/dice-sheet.png`（三种材质并排，各附一张叠了数字 17 的示意）。先把 A 的候选 01 装进 `client/images/` 让游戏能显示，最终由设计负责人选。

## 2. 数字
- 数字不画进图里，用文字叠在留空的正面三角上：衬线体、粗，带"刻进去"的效果（内阴影＋细高光），颜色随材质（暗红／金／银），作为 CSS 变量，换材质只改变量。
- 翻滚时不显示数字（或只显示快速闪动的模糊数字）；落定后数字淡入。

## 3. 动作（替换 039 的 SVG 旋转）
- 托盘先淡入；骰子从上方落下，弹跳 2 次，转速逐渐变慢：用 rotate＋轻微的 scaleX/scaleY 挤压模拟三维翻滚；高速阶段加一点 blur。
- 骰子下方有椭圆阴影，随"高度"放大缩小、变淡变浓。
- 落定时有一次小幅的摇晃后静止，然后数字淡入，再按 039 的节奏显示「＋修正 ＝ 合计」「DC　成功／失敗」。
- 等待服务器返回时，骰子在托盘上持续翻滚（不落定）；返回后再走落定流程。最少时长、短版、停留、跳过、`prefers-reduced-motion` 的规则全部沿用 039。
- 优势／劣势：两颗骰子一起落下，落点左右错开；被采用的那颗保持原样，另一颗变暗、缩小一点。
- 自然 20：金色光晕从骰子内部扩散，数字发光；自然 1：换成"裂开"的变体并轻微震动。`critical_enabled: false` 的行动不做这两种效果（同 040）。
- 只用 CSS 和现有的 JS，不引入新库、不用 WebGL；图片总大小控制在 1.5MB 以内（必要时压成 WebP，保留 PNG 原图在 candidates 里）。

## 4. 不做什么
- 不加声音（等设计负责人决定）。
- 不改判定规则、剧本、prompt。战斗的演出不动。

## 5. 验收与汇报
- 截图或录制不了时，至少用 `tests/player_dice_roll.test.js` 的方式验证各阶段的 class／元素切换和时长；视觉验收由设计负责人在浏览器里做。
- `python -m unittest discover -s tests -q`、`node --check client/app.js` 通过；更新 `?v=` 缓存键。
- 汇报：各图的路径和大小、动作各阶段的时长、哪些参数（弹跳高度、转速、阴影）放在 CSS 变量里方便调整。
