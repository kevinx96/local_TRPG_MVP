# 041 NPC 可攻击、二次确认与守護の竜騎士

来源：用户（2026-10-19）：玩家经常用自由输入攻击普通或关键 NPC，现在没有任何后果。除会影响主线的人物外都可以被杀；杀死城镇人物的玩家会在イグニス战后被竜騎士拦截（中间不能休息，难度介于イグニス和将军之间）；竜騎士平时在オークスドーン，普通玩家和他只有闲聊，杀过人的玩家和他对话会强制开战。确认步骤直接给两个选项，选「是」就开战，不再调用模型。

设计全文（分类表、数值模板、全部日文文本、竜騎士的两阶段数值和美术描述）见 `docs/design/npc-combat-v1.md`，**文本照抄**。两份剧本同步修改，用幂等迁移脚本（`scripts/scenario/npc_combat.py`）生成，测试检查重跑不改变剧本。依赖 040 完成。

## 1. 自由行动：attack 操作
- `operation` 增加 `attack`，`target_id` 为当前场所人物的 ID。prompt 措辞按设计文档第 7 节逐字加入。
- 冻结 benchmark 重放保持旧的 operation 列举和 prompt（参照 `item_mechanics.LEGACY_ELEMENT_IDS` 在 `scripts/eval/run.py` 里的做法）。验收：`--variant guard_rules --split dev` 重放仍是 194/194 命中缓存，严重度分布与 2026-10-12 的报告一致。
- 默认 prompt 改了，跑 `python -m scripts.worker_fingerprints` 更新指纹，汇报里写明 Worker 需要重新部署（部署由设计负责人做）。
- 在 `eval/candidates/` 新增约 24 条攻击类候选用例（明确攻击各类人物、玩笑、威胁、假设、否定、对保護人物），标为 proposed，标准答案留给设计负责人审定。

## 2. 人物战斗数据与流程
- 每个人物按设计文档第 2、3 节写上分类、模板数值、守护者、倒下后的结果和城镇标记。
- 流程按第 4 节：保護直接给固定叙述；其余先确认，确认的两个选项都由引擎生成，选「攻撃する」直接开战，**不调用模型**；战斗结束后沿用现有的结算叙述。反逆确认后直接进入 `treason` 结局。
- 人物立绘直接用作战斗图（`npc_*.png`）；守護団の衛兵用现有的城塞士兵类图片，没有就先用 `npc_walter.png` 占位并在汇报里列出。
- 同伴是守护者时离队并作为敌人出手。

## 3. 后果
- 按设计文档第 5 节：人物消失、选项和委托隐藏、商店关闭与柜台物品、尾声的一行文字、`town_blood`。
- **逐一检查**被杀或逃走的人物之后还会登场的剧情场景（例如イアン的「砕けた氷の太刀」、ミーナ的洞窟、ガルド的森狼事件、リーゼ与エリオ的入队），保证离开场景的选项都还在、不会卡死。不确定写法的地方先用简短的占位文本，并在汇报里列成表（场景、人物、你的处理），由设计负责人补写定稿。
- 离线通玩脚本增加一组"在王都杀死店主"的路线，确认能通关、会遭遇拦截。
