# 015 森林地图化、封印洞窟、4 条 NPC 支线

按 `docs/design/forest-v3.md` 实施。日语正文**逐字使用**；文档没给的文字（intent_keywords、preview 等）沿用现有风格补写，并列进推断清单。两份剧本同步修改。任务量大，建议分 4 次提交：①地图系统 ②森林重构 + 洞窟 ③支线 ④数值。

## 1. 地图系统（forest-v3 1.2）
- 剧本顶层 `maps`；`public_session` 返回当前所在的地图（按 `location_ids` 判断）和可见性（visited / adjacent-unknown / hidden / locked）。"去过"按会话里的 `visited_locations` 记录（新字段，旧存档用现有的位置历史或空集合推导）。
- 新接口 `POST /api/sessions/{id}/map/move {"node_id"}`：节点相邻、有 `action_id`、并且这个动作当前可以执行时，执行该动作（和点击按钮走同一个处理流程）；否则返回原因。
- 前端：MAP 按钮、全屏地图、地下城里的常驻小地图、子地图的路径导航（forest-v3 1.2 的界面规格）。只用 `client/styles.css` 里已有的变量。**记得更新 `index.html` 里静态资源的版本号**（012 里漏了，导致浏览器继续用缓存）。
- 写测试：可见性推导、点击移动（成功和各种失败）、子地图切换、旧存档兼容。

## 2. 森林重构与洞窟（forest-v3 1.1、第 2 节）
- 按 1.1 的表格改造 F1–F5 的连接；砦从 F2 进出（最后回到 F2，另外开放到 F5 的近路），洞窟从 F3 进出。
- 洞窟 C0–C5 全部的地点、动作、观察对象、敌人、物品（2.2–2.4）。洞窟里战败不 game over（C5 按 2.2 处理；C1、C3a、C4 的战败也同样处理：HP 1，回到 F3）。
- 虹晶樹的颜色轮换（2.3）：引擎支持敌人的 `resistance_cycle: {"every": 2, "phases": [...], "log": "..."}`。实现不了就按文档的退路处理，并说明。
- 虹晶武器（2.5）。
- 里程碑 Lv2 的触发点改到 F4 通过时（1.1）。
- 更新 `checkpoints`、`key_items.json`、`redundancy.py` 的路线定义（森林现在是一条主线加两条可选支路）。

## 3. NPC 支线（forest-v3 第 3 节）
- 4 条支线的所有动作、观察对象、同伴、商店、任务日志。
- 引擎需要的新功能：店铺折扣（由 flag 打开的 `discount`）；"在某商店买过东西"的 flag（`on_purchase_flag`）。
- `heard_gald_rumor` 加入揭发条件的线索 flag（scenario-v2 3.5）。
- 测试：每条支线的**每一种开始方式**都能开始、都能完成；支线 2 在没接任务时也能交付；支线 3 的两个分支各自的后续；支线 4 已经买过鎧时的替代奖励。

## 4. 数值（forest-v3 第 4 节）
- 新敌人的数值；`targets.json` 增加洞窟的遭遇和"Lv1 硬闯虹晶樹 < 0.35"这条约束；虹晶武器对イグニス战的提升 10–20pp。
- 主线连续通关率检查：加入支线奖励以后，不能超过上限 0.80；超过就削减奖励。
- 报告 `eval/reports/balance-<日期>-forest-v3.md`。
