# 009 数值第四轮：以连续流程为主要目标

## 设计决定
pass3 的连续流程模拟说明，单场数值已经接近目标，真正的问题是**消耗累积**：主线通关率是勇者 24.8%、魔法使 21.6%、僧侣 5.6%、盗贼 1.2%，失败集中在霜狼战、森林狼战和最终 Boss。哥布林砦路线在第四层几乎全灭。

所以从这一轮起，**连续流程通关率作为主要目标**，单场指标降为辅助：
1. 主要目标（写进 `targets.json` 的新键 `route_targets`）：
   - 主线（经过森林狼战的路线）每个职业的通关率 [0.55, 0.80]
   - 哥布林砦路线每个职业的通关率 [0.40, 0.75]
   - 各职业通关率的最大差值 ≤ 0.20
2. 单场指标里，只保留胜率区间、职业差距、Boss 普攻上限作为硬性要求；`hp_left` 和 `rounds` 改为只报告、不判定（`--check` 里加开关，默认不判定这两项）。
3. 新增可调手段（允许修改剧本）：
   - **休息点**：在现有地点里，给已经有休息或回复语义的动作（宿屋、泉、回复阵）补上或调整回复量。可以考虑在村庄篇的霜狼战之前、竜の谷之前各确保有一处可用的休息点。只能用现有地点和现有动作；需要新增动作时，列出来标 `TODO(design)`，不要自己加。
   - **药草和回复品的获取**：商店价格、库存、战斗奖励里的回复品数量。
   - 和 005 一样的敌人数值范围。
4. 不改：技能名称和定位、里程碑等级、剧情文本（005/007 已经允许的数字同步除外）、xanxus/warlock 两场战斗。

## 实施
- 先把第 1、2 条写进 `targets.json` 和 `--check`（`route_targets` 的读取写测试）。
- 用 `scripts/balance/route.py` 做搜索的主要评价函数；单场矩阵用来确认胜率区间没有被破坏。
- 每处改动记录原值 → 新值和理由。

## 报告
`eval/reports/balance-<日期>-pass4.md`：各路线、各职业的通关率（和 pass3 对比）、失败点分布、到达最终 Boss 时的资源、改动清单、单场胜率的变化。

## 验收
两条验证命令通过；route_targets 达标情况在报告开头列出；没达标的写明原因。

## 汇报要回答
1. 各路线、各职业的通关率（前→后）。
2. 加了或调了哪些休息点、回复品。
3. 单场胜率有没有因此跑出区间。
4. 其余按 `docs/roles/engineering.md` 的汇报格式。
