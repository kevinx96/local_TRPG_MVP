## 1. 敌人状态
### 1.1 规则
- **触发方式**（只用现有机制）：
  - **命中**：给普攻或已有技能的 `on_hit_status` 加 `chance`（经 G1 用覆盖层写入）。造成伤害后才结算，护盾完全吸收、或抗性为 0 时不会附加。
  - **周期**：新增一个 normal-only 技能，带 `every_n_rounds: N`。引擎会在第 N、2N… 回合强制使用它，其余回合退回普攻（要有测试证明这一点）。敌人没有冷却字段，这就相当于冷却。
  - **加权**：已经有技能的敌人，新增技能用 `ai_weight` 或 `max_uses_per_battle`。
- **已经有技能的敌人永远用不到普攻**（`_choose_enemy_ability` 只在没有可用技能时才普攻），所以它们的状态要挂在技能上。
- 精英如果已经有 052b 的 `every_n_rounds` 百分比招式，本 spec 就不再给它加 `every_n_rounds` 技能（引擎会按列表顺序取第一个匹配的技能，两者会冲突），改用命中附加。
- **Boss 最多 1 个带状态的技能**；Boss 不施加気絶。玩家对 Boss 施加気絶的规则不变（需要 `status_allow`，每场 1 次）。
- **気絶只挂在 052b 的预告招式或百分比招式上**（skills-v2 §6、052 §3.3），而且只给精英。
- **森林前半段保持温和**：F1、F2 的杂兵和 F4 的森狼都不带状态。
- 状态本身的数值（每层伤害、持续、上限）以 `status_defs` 和 `status-texts-draft.md` 为准；下表只写每次附加时的 `chance`、`stacks`、`duration`。

- 解除道具都是 `kind: cleanse`，**只能在战斗中使用**（战斗外的 `use_item` 只支持 heal / restore，见 G3）；陷阱附加的状态留到下一场战斗开始时生效，到时可以用道具或技能解除。

### 2.4 僧侶的存在感
| 手段 | 怎么让僧侶更有价值 | 非僧侶 的较弱替代 |
|---|---|---|
| 清めの鈴（Lv1 起） | 每 2 回合可以花 3 MP 解除一个减益，不消耗金币；Lv5 之前 浄化 还没学会，这填上了空档 | 单项解除药（每次花钱、占行动） |

## 3. 陷阱与落石
### 3.1 规则
- 每个陷阱都是一个 **normal-only 的可选新行动**，带 `hazard: {kind, warning}`。选项上会显示警告（客户端已经支持 `hazard.warning`），玩家知道有风险也可以去碰。
- **不在必经路线上收"伤害税"**：每个陷阱都守着一份额外奖励，或者是一条近路；不碰它也不影响主线。已有的必经行动一律不改。
- 判定按 checks v2：易 8、中 10、難 12、至難 14。失败效果用 051 的 `damage_player`（`max_hp_ratio`，非战斗伤害不致死）和 `apply_status`（留到下一场战斗开始时生效）。
- **成功与失败都拿到奖励**，失败只多付代价（近路类除外：失败也能到达，但要扣 HP）。
- 发现 / 规避手段写成 `roll.advantage` 条件（引擎已支持 `requirements` + `reason`）：
  - **盗賊**：`{character_id: thief}`，理由「盗賊の勘」【仮】；另外 盗賊 对 軽業 / 隠密 有熟练加值。
  - **探り棒**：`{has_item: 探り棒}`，理由「探り棒で確かめた」【仮】。
  - **线索**：同一地点已有的观察 / 判定行动成功后设置的 flag（下表"线索"列；工程查出实际 flag 名，没有 flag 就跳过这一项）。
  - 同伴的协助优势照旧生效（ロビン 知覚、エリオ 知覚 / 調査 等）。
- 每个区域最多 2 个；森林、オークスドーン、竜の谷 不放。
