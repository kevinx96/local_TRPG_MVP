## 1. 定位：学术优先，产品只做可公开的 demo

研究问题（暂定）：
> **在有限提示词预算和低延迟约束下，把 GM 职责中的哪些部分移交给确定性引擎，能在保持玩家开放输入自由度的同时，最大化裁定准确性和叙事一致性？**

可写的贡献点：
1. **引擎裁定型 LLM GM 架构**：模型只输出受 schema 约束的意图，引擎负责结算。把这种做法与"模型直接写 state_delta"（现在的 Full 模式就是天然对照组）做对比。
2. **提示词预算与准确率曲线**：契约长度、上下文打包方式、few-shot 数量，分别对准确率、延迟、成本的影响。
3. **注入免疫**：因为状态由引擎持有，提示注入最多只能污染文本，污染不了数值。这一点可以量化。
4. **小模型 + 引擎 vs 大模型自由 GM**：用现有的 Ollama 模型（qwen3-swallow-8b、elyza-jp-8b、qwen2.5-7b/3b）作为对照组。
5. **决策模型（Jev 类）承担裁定**：意图解释本质上是从封闭候选集里做选择（kind/action_id/target_id/item_id 都是枚举），适合用只计算候选概率、不生成文本的决策模型（例如 NeoHorse-Jev-4B），速度为毫秒级，而且能直接给出置信度，置信度低时自动走 clarify。生成模型只负责叙述文本。

产品范围收敛为：**单剧本，一小时流程，3 名可选角色，有完整结局**，可以在线游玩。多人、房间、账号体系都往后推。

### P4 战斗数值平衡
**现状模拟**（初始角色、只用普攻、不带同伴和道具，每组 300 场，脚本见 scratchpad 的 `sim.py`，将交给 Astra 正式化）：

| 敌人 | 勇者 | 僧侣 | 魔法师 | 盗贼 |
|---|---|---|---|---|
| slime | 100% | 100% | 100% | 100% |
| goblin | 99% | **48%** | 76% | 99% |
| forest_wolf | 93% | **3%** | 23% | 75% |
| hobgoblin | 30% | 0% | 0% | 10% |
| slime_king / goblin_king | 24% / 0% | 0 | 0 | 5% / 0 |
| 元素、霜狼、伊格尼斯（120HP） | 0% | 0% | 0% | 0% |

问题：① 职业下限差距过大（僧侣打哥布林只有一半胜率）；② 没有成长曲线，中后期敌人全部打不过；③ 防御是"伤害减固定值，最低 1"，低伤害职业被防御吃光，很容易出现极端结果。
注意：xanxus 是剧情上就该输的战斗，warlock 救场战是另一套数值，模拟时要按遭遇类型（杂兵/精英/Boss/剧情必败/操控角色）分别设定目标，在 `locations[].combat` 里加 `encounter_class` 字段标出来。

方案：
- [Claude] 定数值目标（按遭遇类型）：
  - 杂兵：合理操作胜率 ≥95%，剩余 HP 60–85%，3–4 回合。
  - 精英：胜率 75–90%，剩余 HP 30–50%，5–7 回合。
  - Boss：满配（同伴 + 道具 + 技能）胜率 60–75%，8–12 回合；只用普攻胜率 <20%，迫使玩家用上机制。
  - 职业间对同一遭遇的胜率差 ≤15 个百分点。
- [Claude] 成长方式：**里程碑升级**（剧情 flag 触发，引擎执行，模型不参与），全程 4–5 级；每级 HP +20–25%，主属性 +1–2，在第 2、4 级解锁技能。比经验值系统简单，也和剧本结构绑定。
- [Claude] 公式调整：防御改为 `max(ceil(raw*0.25), raw - def)`，或改为比例减伤 `raw * 10/(10+def)`；以模拟结果为准再选。
- [Astra] `scripts/balance_sim.py`：几种策略（只普攻、贪心技能、启发式 AI：残血喝药、Boss 前先上 buff），覆盖每个等级 × 职业 × 遭遇的矩阵；输出热力图和 CSV；接入测试，数值超出目标区间就失败（作为数值回归保护）。
- [Astra] 按模拟结果迭代调参：只改数据，不改引擎，改动由 Claude 审核。

### P5 剧本完善
- [Claude] **剧本制作标准**（写进 schema 和文档）：
