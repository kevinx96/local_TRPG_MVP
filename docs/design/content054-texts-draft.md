### 4. 核对说明与不确定项（中文汇报）

#### 一、较不确定的条目与取舍说明
1. **`poison_dart`（毒矢）与 `smelling_salts`（気付け薬）的说明粒度**：
   - `毒矢` 原文案为 `"1ダメージを与え、戦闘終了まで毎ラウンド4ダメージの毒を付与する。"`。在 Normal 难度 v2 状态体系下改为赋予 2 层 `poison`。为遵守“不写持续回合与伤害数字”的规范，表中写为 `「敵単体にわずかな物理ダメージを与え、強い毒を付与する。」`；若希望玩家在商店直接看出层数，可将末尾改为 `「毒を2層付与する。」`（字数仍在 20–50 字内）。
   - `気付け薬` 在 Spec 054 §2.2 中写的是 `{tags: ["paralysis", "weaken", "blind"]}` 且未写 `count: "all"`（而 `毒消し草` 与 `万能薬` 显式写了 `count: "all"`）。因此 `気付け薬` 与 `火傷薬` 的文案写为 `「〜を浄化する」` 而不写 `「すべて浄化する」`，避免与引擎实际结算的 `count` 默认值冲突。
2. **TR-02（`cave_heat_corridor`）的成功奖励表现**：
   - 按钮动作是“拾取喷气孔旁的结晶”，但 Spec 054 §3.2 表中配置的奖励只有 `火傷薬 ×2`（没有给結晶道具）。为了不让玩家产生“文字里写拿到了结晶、背包里却只有火伤药”的割裂感，成功文案写成了趁热气停歇伸手探向结晶旁、捡起前人掉落的药壶（`誰かが落とした軟膏の壺を無事に拾い上げた`）。若后续在奖励中加回结晶，可把最后一句改为 `結晶とともに軟膏の壺を拾い上げた`。
3. **TR-06（`ghoul_marsh`）与 TR-09（`mansion_study`）的麻痹来源**：
   - 两处失败效果均为 `HP -10% + 麻痺`，但一个是沼泽沉箱（运动检定）、一个是将军书房保险箱（轻业检定）。为贴合各自场景，TR-06 写成泥中箱缘暗藏的毒痹针（`痺れ針`），TR-09 写成锁孔内的防盗电击针（`放電針` / `雷撃`）。

#### 二、Spec 054 与 `dragon_rpg.json` / 引擎现状的不一致点
1. **052b 的百分比技能尚未合入 `dragon_rpg.json`（涉及 3 个 `★` 気絶技能）**：
   - Spec 054 §1.2 中 `hobgoblin`、`rock_giant`、`ice_sentinel` 标注为“挂在 052b 的百分比招式上；若未给百分比招式则新建重击技能”。
   - 核查当前 `dragon_rpg.json`（版本 `2026-10-21-sword-049`）：`ice_sentinel` 已有技能 `ice_hammer`（`氷槌`），可直接挂载；但 `hobgoblin` 与 `rock_giant` 的 `skills` 目前仍为空数组 `[]`。因此在表 1 中额外提供了这两个敌人的备用新建技能名与发动描述。
2. **`xanxus_phantom`（ザンザスの分身）的「火炎旋渦」并非攻击技能**：
   - Spec 054 §1.2 要求在 `xanxus_phantom` 的 `命中：「火炎旋渦」` 上挂载 `burn`（100% 火傷）。
   - 但在 `dragon_rpg.json`（第 21675 行）中，`flame_vortex`（`火炎旋渦`）的 `kind` 是 `"field"`（领域技能，每回合初造成 3 点固定伤害），**不走 `_resolve_attack` 命中判定**。按 Spec §1.1“造成伤害后才结算 `on_hit_status`”的规则，直接挂在 `flame_vortex` 上不会触发。工程实现时需在 `_execute_enemy_ability`（展开 `field` 时）或 `_apply_enemy_fields`（领域伤害结算时）补充 `on_hit_status` 处理，或改挂到其普攻 `炎の弾` 上。
3. **陷阱线索行动（`clue_flag`）在 `dragon_rpg.json` 中的 4 处偏差**：
   - **TR-01（`goblin_fort_second_choice`）**：Spec 写线索来自 `listen_fort_corridors` 成功，但 `dragon_rpg.json`（第 7726 行）中该行动的 `success_effects` 为 `[]`，**没有设置任何成功专属 flag**（只有行动级 `"once": "listen_fort_corridors_done"`，无论检定成功或失败都会置位）。若要严格按“检定成功才给优势”，需给 `listen_fort_corridors.success_effects` 补一个 `set_flag`，或按 Spec §3.1 跳过该项。
   - **TR-05（`bone_field`）**：Spec 写线索来自 `identify_old_banner` 成功，但 `dragon_rpg.json`（第 14967 行）中该行动成功后只发放道具 `rusted_badge`（`錆びた兵士の徽章`），**未设置 flag**（其 `"once": "found_banner_badge"` 同样在失败时也会置位）。工程端可改为检查 `has_item: "錆びた兵士の徽章"`，或在 `success_effects` 中补 `set_flag`。
   - **TR-04（`burning_house`）与 TR-07（`gorge_rockfall_path`）的线索行动在前置地点**：
     - TR-04 引用的 `read_fire_spread`（设置 `fire_upwind_known`）实际在 `village_approach`（第 9035 行），不在 `burning_house`。
     - TR-07 引用的 `count_tremors`（设置 `gorge_tremor_rhythm`）实际在 `gorge_entrance`（第 17710 行，另 `oaksdawn_inn` 的 `swap_tales_elio` 也设置同一 flag），不在 `gorge_rockfall_path`。由于 `session["flags"]` 全局保留，这两处直接引用上述 flag 名即可正常工作。
   - **TR-08（`gorge_miner_camp`）**：`search_miner_camp`（第 17983 行）是免检定行动，无 `set_flag`，而是通过 `"once": "read_miner_diary"` 将 `"read_miner_diary"` 写入 `session["flags"]`，工程直接用 `"flag": "read_miner_diary"` 即可。
4. **敌人攻击类技能的发动描述日志**：
   - 目前 `host/combat.py` 的 `_execute_enemy_ability` 在执行敌人 `attack` 类技能时直接调用 `_resolve_attack` 输出伤害行（`"{name}が{defender_name}に{damage}ダメージ。"`），尚未输出技能自身的发动描述文本。若要在战斗日志中显示表 1 的 `{enemy}` 发动描述，需由工程在技能结算前追加一条日志或接入技能 `description`/`log` 字段。
