# 提示词变更记录（设计负责人）

每次修改默认提示词都记在这里：改了什么、依据哪些数据、在冻结 test 上的复验结果。旧版本通过评测变体保留，便于复现。

## 2026-10-11：意图解释提示词加入防误触发规则
- **改动**：`host/free_actions.py` 中，`PLAN_PROMPT = PLAN_PROMPT_BASE + "\n" + PLAN_GUARD_RULES`。追加三句：
  - 否定、等待、条件句的输入不要求替代行动；不选择有代价或有风险的操作，改为 dialogue
  - 「〜したら」「〜なら」这类条件行动现在不执行
  - 不使用背包里没有的物品，也不用别的物品代替
- **动机**：Gemini 3.1 Flash-Lite 在 v1 和 v2 上都稳定出现三种 S3：否定被理解成"改用别的手段"、缺少道具时自行替换、条件句被立即执行。
- **dev 结果**（v2 dev，194 条）：

  | 变体 | S0+S1 | S3 | InvalidPlan | 输入 token | 每回合 USD |
  |---|---|---|---|---|---|
  | pre_guard（旧默认） | 89.7% | 3.1% | 1.5% | 706 | 0.000302 |
  | guard_rules（现默认） | 92.8% | 0.5% | 1.0% | 769 | 0.000319 |
  | guard_rules_short | 90.2% | 2.1% | 1.5% | 728 | 0.000305 |
- **test 复验**（v2 test，292 条，冻结）：

  | 变体 | S0+S1 | S3 | InvalidPlan | kind | 每回合 USD |
  |---|---|---|---|---|---|
  | pre_guard | 83.6% | 2.1% | 7.2% | 86.3% | 0.000290 |
  | guard_rules | 84.6% | 1.0% | 4.1% | 90.8% | 0.000310 |
- **结论**：所有指标都没有变差；S3 在 test 上减半，在 dev 上降了 83%。代价是输入多约 63 token（+9%），成本 +5.5%，p50 延迟 +0.15 秒。test 上 S3 的条数是 6 对 3，样本小，**不能声称统计显著**。以后需要用更大的 test 集或多次采样来确认。
- **复现**：旧提示词用评测变体 `pre_guard`；报告见 `eval/reports/008-gemini-guard-compare.md`、`eval/reports/008-gemini-guard-test-compare.md`。

## 2026-10-12：评分 v1.2 与契约归一化（不改提示词）
- **改动**：
  1. 评分：对话、反问、拒绝的 gold 里 target_id 为空时，不比较 target_id。
  2. 标注：不可能的行动、注入，用 dialogue 拒绝算 S1。
  3. 契约（游戏行为）：`parse_plan` 对 kind=existing 并且有 action_id 的计划，把多余的 operation/target_id/item_id/advance 归一化掉，不再判为 InvalidPlan。
- **冻结 benchmark 离线重算**（同一批缓存响应，guard_rules 提示词）：

  | split | S0+S1 前 → 后 | S3 前 → 后 | InvalidPlan 前 → 后 |
  |---|---|---|---|
  | dev | 92.8% → 95.4% | 0.52% → 0.52% | 1.0% → 0% |
  | test | 84.6% → 94.5% | 1.03% → 1.37% | 4.1% → 0.3% |
- **贡献拆分**（test，净 +29 条，247 → 276）：评分 1 = +15 条，标注 2 = +4 条，契约 3 = +10 条；dev 上分别为 +3、+1、+1。**一半以上的提升来自修正评分里的误判，不代表模型变好**。论文里要分开报告：评分修正前后的数字、契约修改的净效果。
  - 更正（2026-10-12）：这里原来写的是 +31 / +10 / +3（合计 44，和净增 29 对不上）。当时统计的是"修订后判对、并且属于某一类"的条目，没有扣掉修订前就已经判对的那部分。正确的拆分由论文初稿的逐条重算得出。
- **契约修改的代价**：test 里有 1 条原本是"格式无效、什么都不执行"，现在被执行成有害动作（v2-sequential-013：跳过了第一步）。净效果是 +10 条正确、+1 条 S3。保留这项修改。
  - 更正（2026-10-12）：原来还把 v2-negation-018 算作归一化造成的。实际上在归一化之前（run 193815），它就已经是解析成功的 S3。
- **秘密动作（018）**：解锁前不出现在给 planner 的 actions 里。补充集的 evidence_claim 一类，S3 从 5/8 降到 0/8；补充集整体的 S3 从 12% 降到 2%。同一个问题，用提示词约束（`guard_claims` 变体）无效，补充集 S3 反而从 5/8 变成 6/8。**在动作列表上隐藏信息，比用提示词约束更有效**。

## 2026-10-12：顺序动作规则（PLAN_SEQUENCE_RULE）
- **改动**：`PLAN_PROMPT = PLAN_PROMPT_PRE_SEQUENCE + "\n" + PLAN_SEQUENCE_RULE`，追加一句：
  「AしてからB」「Aした後でB」のように順番のある入力では、最初の行動Aだけを選ぶ（Aが薬草などの所持品の使用なら interact の use_item）。Aを実行できなければ clarify。
- **动机**：当前剧本版 v2 的 sequential 一类有 5/20 为 S3（「薬草を使ってからX」时执行了 X，跳过了药草）。
- **措辞的迭代**（当前剧本版 v2，486 条）：
  | 变体 | S0+S1 | S3 | InvalidPlan | sequential |
  |---|---|---|---|---|
  | default（加规则前） | 95.1% | 1.23% | 0% | 13/20，S3 5 |
  | guard_sequence（只说"选第一步"） | 94.7% | 0.41% | 0.62% | 16/20，S3 1 |
  | **guard_sequence_item（加上"用道具就是 use_item"）** | **96.5%** | **0.41%** | **0%** | **20/20，S3 0** |
  - 第一版的问题：模型确实想先做第一步，但把"用药草"填成了 kind=existing，或者填了不存在的 action_id，变成 InvalidPlan。补一句表示方式就解决了。
- **冻结 benchmark 复验**（评分 v1.2）：
  | split | S0+S1 | S3 | InvalidPlan |
  |---|---|---|---|
  | dev | 95.4% → 95.9% | 0.52% → 1.03%（1 → 2 条） | 0 → 0 |
  | **test** | **94.5% → 96.6%** | **1.37% → 0.68%** | 0.34% → 0 |
- **结论**：test 上三项指标全部改善，采用。dev 的 S3 从 1 条变成 2 条，在样本误差内。代价是输入 token +45（约 +6%）。
- **复现**：旧提示词用评测变体 `pre_sequence`；`guard_rules`、`guard_claims`、`guard_sequence` 都已固定在加这条规则之前的提示词上。
