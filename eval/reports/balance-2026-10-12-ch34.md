# 019 工程与数值报告（2026-10-12）

## 1. 完成了什么

两份剧本同步实现第 3、4 章地图、避难所与 5G 休息、リク支线及竜の秘薬、D1–D4 与岩棚支路、Xanxus 后续与火种任务。设计提供的日语正文逐字录入。旧的竜の谷入口全部改到 D1；D4 旧存档保留当前位置，不重放入口事件或升级。

引擎支持剧情 `remove_item: {name, quantity, force: true}`、按最大 HP 比例回复、僧侣 MP 条件，以及入口条件跳转与确定性入口叙述。模型提交的物品移除仍会过滤 `force`。分身胜利与呼叫ワーロック移除火种；败北 HP=1、保留火种并视为承诺。承诺后击杀イグニス不发炎核；净化后没有炎核，不触发夺核。

默认提示词、benchmark 标准答案、既有角色与既有敌人数值均未修改。特别核对イグニス记录未发生改动。新图使用未来文件名和现有占位机制，没有生图或新增依赖。

**数值验收尚未全部达标**：分身战四职业均在 [0.60, 0.75]；D2b 四职业均在 elite 区间；D1 盗贼超过上限。主线多种准备路线仍低于 017 的下限，未通过修改目标或削弱イグニス消除差距。

### 离线评测方法

- n=500/职业/遭遇或路线，seed=20261012，现有 heuristic 策略，flat 防御。
- 单场按真实动作重放生成 Lv5 checkpoint，再回满资源。分身 checkpoint 实际接受火种、消耗一瓶聖水后入战；不使用凭空配置的装备。
- 连续路线从初始角色开始，战斗逐场实际结算，保留 HP/MP/SP、金币和道具消耗；只有引擎原有升级、明确休息或道具使用可以恢复。
- 吊桥使用同一 trial RNG 实掷 1d20+dex，失败实际扣 6 HP。其余已有叙事判定继续采用 checkpoint 指定结果；救リク路线条件为救援判定成功。因此这些结果不是所有叙事分支的无条件成功概率。
- 基线在修改剧本前运行，与已有 forest-v3 报告的主线结果一致。前后使用相同 n、seed、终点与战斗策略；新增吊桥判定纳入后测。
- JSON 保存每职业的失败地点、到达 boss 时的资源、消耗、示例轨迹和输入 SHA-256。固定种子的 500 次抽样仍有抽样误差，胜率约 70% 时标准误约 2 个百分点。
- 数值评测结束后仅将 D1/D2b 的失败结局提示改为其已有的「竜の谷で力尽きた。」，避免错误指称死于イグニス；不改变任何数值或跳转。JSON 的 `post_evaluation_changes` 单列该文本修订后的剧本指纹，原 `fingerprints` 保留真实评测输入。

## 4. TODO(design)

1. 主线多条路线未达 [0.55, 0.90]；需确定今后的标准准备路线，以及是否允许调整既有补给/资源或其他数值。当前没有削弱イグニス，也没有修改角色或旧敌人。
2. D1 盗贼 93.8% 超过 elite 上限 90%；其余三个职业已达标。继续收紧盗贼又保持指定 physical×0.5、其他职业和连续路线目标，需要设计确认取舍。
3. `call_warlock` 同时需要接受火种和曾被ワーロック救过。现有村庄分支接受/拒绝火种互斥，且 `xanxus_encountered` 隐藏再次进入动作；通常的新游戏路线无法自然同时得到两个 flag。实现保留文档条件，测试组合状态；没有擅自开放复访。无火种的救援玩家有正常可达的短暂现身路线，并纳入 redundancy。
4. 净化动作正文称火种已被烧除，而败北正文要求火种仍在。本实现以文档的胜败效果为准，胜利后才正式移除；战斗期间仍保有火种及其抗性。请确认是否希望改正文或另设临时抑制效果。
5. 进入 D1 的 Lv5 里程碑自动回满 HP/MP/SP。5G 休息仍能减少冰精灵/巨狼之前的消耗，但不能直接恢复 D1 后至イグニス之间的消耗。保留既有升级规则，未额外插入恢复点。

## 5. 推断清单

- 文档未提供的 action id 使用 `fight_ash_wraiths`、`sneak_through_ash`、`enter_dragon_nest`、`continue_after_warlock`；新增 quest id 为 `side_riku`、`fire_seed_curse`。内部辅助 flag 使用 `nest_event_seen`、`xanxus_nest_seen`、`elder_mourning`、`xanxus_core_scene_seen`、`xanxus_denied_core`。
- preview 与 intent_keywords 复用动作日语原文，不另写叙事；D1 战斗按钮用现有「戦う」，短暂现身后的按钮用现有「先へ進む」。普通战败补写「竜の谷で力尽きた。」并沿用现有竜の谷失败结局结构；D1/D2b 胜利提示复用下一地点 description。
- 三张新增背景用对应未来文件名；D1 沿用谷背景，D2b 暂用吊桥背景。短暂现身复用既有ワーロック立绘；温泉引用设计表中 `bg_hot_spring.png`。
- 地图坐标按现有布局约定安排；D3 收纳 Xanxus事件、分身战和短暂现身三个子状态，不额外创造地图节点。边调用已有动作，自动战斗推进的边不提供绕战点击。
- 补全第3章 scene 的 `location_ids` 中遗漏的 `village`，使避难所 NPC 与长老条件描述进入上下文；未改变其地点 ID 或场景归属。
- 短暂现身采用独立文字地点，进入自动给线索，点击「先へ進む」回 D3；每个玩家的 D3 首访分支只判断一次。火种已移除的异常/迁移状态不重新受诅咒。
- 僧侣同时有聖水和 6MP 时优先消耗一瓶聖水；没有聖水才扣 6MP。分身败北不退还支付。
- `accepted_fire_seed` 保留为历史 flag，移除状态另用 `fire_seed_removed`；已经解除火种的玩家即使还保留承诺 flag，也不会被夺核。
- 竜の秘薬回复量为 `floor(max_hp * 0.5)`，封顶 max_hp；背包、自由行动与战斗使用一致。满 HP 时探索使用不消耗。
- 新敌人的 HP、伤害、命中、抗性倍率、AI 权重、状态持续时间、0金币/无常规掉落由工程在 spec 授权范围内设定，明细见上表；普攻名复用敌人名。窒息不叠层，刷新2回合。
- D1/D2b 战斗不开放逃走；D1 的绕战方式为文档给出的潜行判定。两场败北沿用竜の谷失败结局 ID，提示使用通用的竜の谷败北文本。
- 采用现有每职业数值目标口径，而非只看四职业平均值。连续路线中的准备、采购及回复顺序均为评测策略假设，已分别列出，未把它们变成强制剧情步骤。
- 分身用聖水净化后、保留火种抗性、Lv5 满资源的单场胜率作为指定目标的评测口径。它不同于带着 D1 损耗立即净化后的无休息连战概率。

## 6. 偏离 spec 的地方及原因

- 数值目标没有全部达成，具体项目见第1、4节与 JSON。分身已达标；没有越权修改既有敌人、角色或目标区间来制造达标结果。
- 三种 Xanxus 应对均已实现，但呼叫ワーロック的双 flag 条件在普通新游戏路线不可同时获得；因其需要设计调整，没有新增剧情入口。
- 更新了一项原本就过时的 benchmark 生成测试：已审阅的 `eval/candidates/intent_v2_current.jsonl` 不再被要求与“needs_review”生成结果逐字相等。仍严格验证临时生成结果等于原始标签副本、快照一致、源标准答案不变；没有修改候选或标准答案数据。
- 使用一次完整工程提交交付；用户建议的三次提交是可选方案。
