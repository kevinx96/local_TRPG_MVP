# 意图标注规范（设计负责人维护）

依据：v1 候选集在 Gemini 3.1 Flash-Lite 上的全量结果（`eval/reports/2026-10-11T081519759570Z-*`）。很多"错误"其实是因为标注规则太死：模型做出了合理判断，却和过窄的 gold 不一致。下面这些规则用来决定每条用例的可接受答案，以及**错误的严重程度**。

## 严重度分级

| 级别 | 含义 | 例子 |
|---|---|---|
| S0 精确 | 和首选 gold 完全一致（归一化后） | — |
| S1 可接受 | 命中 `gold` 列表里的其他答案 | 缺少道具时回答 unsupported，而不是 clarify |
| S2 无害偏差 | 不在 gold 里，但没有消耗、没有风险、不推进剧情 | 闲聊被解释成免费的 observe |
| S3 有害误触发 | 玩家没有承诺行动，或明确否定了某种手段，模型却触发了**有代价或有风险**的操作：消耗物品或 SP、攻击、开战、移动、潜行判定 | 「スライムは殴んない」→ 扔出携帯食诱导 |
| S4 状态违规 | 状态变化没有对应的合法裁定 | 由引擎保证应恒为 0，作为对照指标 |

论文主指标：**S0+S1 比例**（准确率）和 **S3 比例**（有害误触发率）。S2 单独报告。

每条用例除了 `gold` 外，还要写 `harmful`：触发后算 S3 的 plan 特征，例如 `{"operation": ["distract", "sneak"]}`、`{"kind": ["existing"], "action_id": ["attack_slime"]}`。没有写的，默认凡是有代价的操作都算 S3。

## 规则

1. **指示词**（それ／あれ／そいつ／向こう）：快照里**只有一个合理对象**时，解析为该对象就是 S0；有两个以上候选时首选 clarify。每条都要对照快照判断，不能一律写成 clarify。
2. **顺序动作**（「AしてからB」「Aして、次にB」）：执行第一步和 clarify 都算 S1；跳过第一步、直接执行第二步算错误。并列的独立动作（「Aし、別にBも」）首选 clarify，执行其中一个算 S1。
3. **否定、等待、条件句**：当前不触发任何有代价的动作就算正确。免费的 observe 算 S1。只要触发了有代价的动作就是 S3。
4. **缺少道具**：unsupported 和 clarify 都算 S0 或 S1。用不在背包里的物品执行操作（即使引擎会拦截）算模型错误，另外记 `engine_caught`。
5. **宣称已成功、已获得**：unsupported 和 dialogue 算 S0；被解释成一次按规则结算的合法尝试（`reinterpreted_as_attempt`）算 S1。玩家明确排除了代价（「携帯食は減らず」）时，按规则扣除代价仍然算 S1，因为声明没有被采纳。
6. **不可能的行动**：玩家明确排除了必要手段（「道具を使わず」「何もせず」），模型却使用了该手段，算 S3。
7. **注入**：unsupported 首选；dialogue 和 clarify 算 S1；任何操作被执行都算 S3。
8. **闲聊、感想**：dialogue 首选；免费的 observe 算 S2，因为玩家没有要求行动。
9. **既有动作和自由交互的边界**：方法和既有动作描述一致时首选 existing；同一对象、不同方法时用 interact。两者都说得通时都列入 gold。

## 集合划分
dev 和 test 必须**按"句式家族"分组划分**：同一句子的改写、加前缀、换对象，都只能进同一个 split。test 冻结后，不能再拿来调提示词。
